Capabilities

What the engine does

🎟️

Visitor pre-clearance

Cryptographically random access codes with configurable TTL, usage limits, per-method permissions and revocation.

⚖️

Ordered rule engine

Gate online → credential match → not revoked → not expired → method allowed → uses remaining → grant.

🔑

Five reader types

PIN, licence plate, Bluetooth, facial recognition and biometric — modelled as a discriminated union.

📡

Real-time events

Typed WebSocket frames for access, gate-status and invitation lifecycle, with per-gate subscriptions.

🛡️

POPIA-compliant

ID numbers, phone numbers, plates and codes are masked before they ever reach the audit log.

🤖

Hardware simulator

A standalone script that seeds data and bombards the API with a realistic mix of valid and invalid scans.

HTTP API

Endpoints

All request bodies are validated with Zod. Errors share a single envelope: { "error": { "code", "message", "details" } }.

POST/api/invitations/:id/revokeRevoke an invitation ahead of expiry.

Clean architecture

One direction of dependency

The domain never imports Express, ws or a database. A single composition root wires concrete adapters to interfaces, so persistence and transport are swappable.

http/ + realtime/Express routes, middleware, WebSocket hub — the delivery mechanism.
services/Visitor lifecycle, gate state machine, the access-validation rule engine.
repositories/Persistence ports with in-memory adapters (swap for Redis/Postgres).
schemas/ + lib/Zod validation, POPIA masking, config, logging, ids.
types/Domain vocabulary — the single source of truth, zero any.

Compliance by design

POPIA masking on every write

Every audit record passes through a single masking choke-point, so raw personal identifiers are never persisted.

Quickstart

Run it locally in three commands

The full WebSocket app runs anywhere Node runs. Use the CLI, or deploy it with the buttons below.

bash
# clone + install
git clone https://github.com/Teboho-Mohale98/gatekeeper-ts.git
cd gatekeeper-ts && npm install

# start the service (HTTP + WebSocket on :4000)
npm run dev

# in a second terminal: drive it with simulated hardware
npm run simulate
